## 1. [P2] 首页内锚点被栏目路由当作未知地址

位置：`js/main.js:14-21`、`js/main.js:58`、`js/main.js:73-75`；相关入口为 `index.html:13`、`index.html:47`。

复现：打开 `#stories` 或在首页点“读读我的故事”后刷新。初次激活时 `readRoute()` 找不到 id 为 stories 的 panel，把地址归为 about，`activate({restore:false})` 直接滚到页面顶部，无法到达故事区。窄屏上的故事区位于较长的身份区之后，问题更明显。另一个确定路径是在行动与思考等栏目按 Tab 到“跳到正文”并激活；地址变成 `#main` 后同样回退 about，当前栏目被隐藏，跳转错误地返回首页。

原因：点击处理器仅放行两个原生锚点，没有让随后的 `hashchange` 和首次解析理解这些锚点。点击“读读我的故事”当下能否停在目标位置还受原生滚动事件和位置保存顺序影响，因此不以该瞬间表现作为唯一证据；刷新失败由初始化逻辑直接确定。

最小修复建议：明确处理文档内锚点。把 stories 解析为 about 面板内的 stories 目标，并保留其路由／返回位置；跳到正文则只移动到当前显示栏目的正文或标题，不触发栏目切换。核对首页关键词进入后浏览器后退、返回按钮、`#stories` 刷新及其他栏目的键盘跳过导航。

## 2. [P2] 无脚本降级的显示规则被 important 覆盖

位置：`index.html:124`、`css/style.css:19`。

复现：禁用 JavaScript 后刷新。无脚本说明声称“当前显示所有栏目”，但 action、life、music、shares 四个 section 的 hidden 属性仍然生效；导航也无法显示这些内容。

原因：全局 `[hidden] { display: none !important; }` 的优先级高于 noscript 中不带 important 的 `.panel[hidden] { display: block; }`。后者选择器更具体也不能覆盖前者。

最小修复建议：让 noscript 的面板显示规则正确覆盖全局 hidden 规则，或把默认隐藏改由脚本增强完成。禁脚本后验证五栏全部可读，开启脚本时仍只有当前栏显示。

## 待主线程实测的候选问题

**末节是否能成为当前小节。** `js/main.js:89` 的 `updateChapter` 只接受小节顶部进入视口前 30% 的情况（第 93 行），没有页面到底时的末节处理。如果第五节及其之后的内容总高度小于视口高度的 70%，滚到底时它仍不能进入这个阈值，目录可能继续高亮第四节；直接点击第五节同样受页面最大滚动位置限制。建议在 1280×940 或更高桌面视口打开 `design-v2.html#action/cognition/learning`，再滚到底，核对两份认知目录的 `aria-current` 是否落在第五节。此为阈值算法推导的条件性风险，审阅者未测得真实布局尺寸，不记为已确认缺陷；主线程如实测复现，应修复并回归手动滚动和小节跳转。

## 已核对的实现

- 单主题与目录：`js/main.js:117` 起按主题隐藏其他正文；`index.html:79` 的目录独立于阅读区。认知结束后只保留可选相关链接，不接上其他主题全文。两版 action 阅读区经独立文本比较逐字符相同，均有五主题、五个认知小节；完整 HTML 的静态 ID 均无重复。
- 手机目录与焦点：脚本创建原生 `details/summary`，插入标题后；每次激活视图会先收起目录，再定位目标。目标小节在两版均具 `tabindex="-1"`，因此从目录跳转时可把焦点转给正文；返回时只恢复仍可见的来源链接。`css/style.css:235` 起在 960px 及以下替换侧边目录，760px 及以下采用 16px 正文和 20px 内边距。实际键盘、触控及缩放由主线程另测。
- 地址兼容：`js/main.js:53` 的路由解析保留五主题与旧 `#action/environment-experience`；无效主题退到目录，无效小节退到对应主题开头。认知五节分别映射到现有的小节 ID。未发现通过该路由构造出无效 CSS 选择器的正常输入。
- 返回、后退和刷新：`js/main.js:75` 起把位置和来源焦点写入历史条目；站内导航先保存来源再新增条目；同一主题的章节跳读继承文章原来源，跨主题保留上一主题来源。`popstate/hashchange` 有重复激活保护；刷新复用当前文档的历史状态。此处是代码路径核对，不等于真实浏览器历史行为已实测。
- 无脚本与其他栏目：两版末尾 `noscript` 用更具体的规则显示带 `hidden` 的所有栏目；正文在 HTML 内，不依赖脚本生成，因此仍可连续阅读。无脚本时带斜杠的主题/章节地址不具原生锚点定位能力，本方案仅要求正文可读，未把它算作本轮缺陷。兴趣、音乐、工具和项目仍使用原 `.panel` 切换；跳至正文有单独处理，正常点击与带修饰键点击分开。
